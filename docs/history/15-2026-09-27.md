# 作業記録 2026-09-27

## 🆕 UPM の配布を「public リポジトリ + Git URL」へ切り替える土台を作った

これまで client は `unity/` を `file:../../open-audioware/unity`(隣のフォルダ参照)で
取り込んでおり、ネイティブライブラリ(iOS `MwFfi.xcframework` / Android `.so` / macOS
`.dylib`)は各自の手元でビルドする前提だった。安定版を出す準備として、**タグを打てば
ビルド済みネイティブライブラリ入りの配布物を作る**仕組みを追加した。

- `.github/workflows/release-upm.yml` を新設。`v*` のタグ push(と手動実行)だけで動く
  (push / PR では動かない。CI 本体の `ci.yml` とは別)。iOS(xcframework)/ macOS(dylib)/
  Android(.so)を並列ビルドし、`unity/` の中身と合わせて **`upm` ブランチ**(main とは
  別履歴の orphan)へコミット、**`upm/v<version>`** タグを打って push する集約ジョブを持つ。
  タグの版と `unity/package.json` の `version` が一致しないと失敗させる(取り違え防止)
- `.meta`(PluginImporter 設定)は**既に `unity/Runtime/Plugins/**` の該当パスへ
  コミット済み**だった(バイナリ本体だけが `.gitignore` 対象)。配置替えは不要
- `unity/package.json` の `version` を `1.0.0` に上げた。⚠️ **タグはまだ打っていない**
  (楽曲の遅延の修正を入れてから打つ方針)
- README に「UPM での導入方法」(`?path=unity#upm/v1.0.0` 形式の Git URL)と
  「リリース手順(タグを打つだけ)」を追記した
- `docs/integration.md`(ワークスペース内で client と一緒に Rust 側も改造する場合の
  `file:` 参照手順)は対象読者が別なので変更していない

⬜ 楽曲の遅延の修正を取り込んだら `v1.0.0` タグを打ち、`release-upm.yml` が実際に
`upm/v1.0.0` を作れることを一度通しで確認する(このセッションでは push していないため
ワークフロー自体は未実行)
