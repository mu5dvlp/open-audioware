# 0001. セキュリティ枠組みの採用方針 —— ミドルウェアはサプライチェーン検査の継続と、自前脅威モデルでの unsafe FFI / RT スレッドの扱いに限定する

## 状態

採用

## 日付

2026-09-20(ユーザー決定。論点整理は 2026-09-06)

## 文脈

ワークスペース横断で「OWASP、MITRE ATT&CK、ASVS、自前のどれを使うのか」が
`docs/security/SECURITY-FRAMEWORKS.md`(ワークスペース)で整理され、2026-09-20 に
推奨どおり採用が決まった(OWASP API Top 10 + 自前の脅威モデルをいま採る /
ASVS は stg 後 / OGSF は観測のみ / ATT&CK はいまは採らない)。
本 ADR は**その決定のミドルウェア(このリポジトリ)への当てはめ**を記録する。

## 決定

- **OWASP API Top 10 / ASVS はこのリポジトリの直接の対象にしない。** どちらも HTTP API・
  Web アプリケーションの道具で、C ABI を公開するネイティブクレートには当たらない。
- **このリポジトリが受け持つのは次の2つ**:
  1. **サプライチェーン検査の継続** —— CI の `cargo clippy -D warnings` / `cargo-deny` を
     維持する(依存の既知脆弱性・ライセンス検査。THIRD-PARTY-LICENSES.md の一致検査も含む)。
  2. **自前の脅威モデルにおける「unsafe FFI と音声スレッドの健全性」の項目** ——
     FFI 境界の入力検証(不正なポインタ・長さ・列挙値での未定義動作の防止)と、
     RT スレッドの安全性境界(`docs/spec/` の設計2軸)がこのリポジトリの担当範囲。

## 理由

- 枠組みの多く(Top 10 / ASVS / ATT&CK)は**サーバとその運用**に効く道具で、
  ミドルウェアに機械的に適用しても対応する項目がほぼ無い。無理に埋めるより、
  ワークスペースの論点整理が指摘する**実際の空白**に名前を付けておくほうが誠実:
  **このリポジトリのアドバーサリアルな仕掛けは cargo-deny / clippy / ABI ズレ検出のみで、
  `proptest` / `cargo-fuzz` / `miri` / `loom` はすべて無い。**
  一番リスクの高いコード(unsafe FFI と音声スレッド)にファズ・並行性検証が無い、という
  認識を持ったまま割り切る(いま義務にしない)。

## 影響・トレードオフ

- `proptest` / `cargo-fuzz` / `miri` / `loom` の導入は**否定ではなく保留**。着手するなら
  FFI 境界(`mw-ffi` の引数検証)とロックフリー境界(RT スレッドとの共有構造)から。
- OGSF(ゲーム専用の OWASP プロジェクト)の「クライアント整合性」領域が将来
  ミドルウェアへ触れる可能性はあるが、要件文言が固まるまで(目標 Q4 2026)は観測のみ。
- セキュリティ関連の参考資料はこのリポジトリではなくワークスペースの
  `docs/security/SECURITY-FRAMEWORKS.md` 第9節へ足す。
