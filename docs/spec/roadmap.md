## 10. 実装フェーズ

各フェーズ終端で「ビルドが通り、テストが緑」を保つ(テンプレートと同じ運用)。
**各フェーズは独立して中断可能**にする。

| Phase | 内容 | 終了条件 | テンプレートへの依存 |
|---|---|---|---|
| **M0. 基盤** | git init / GitHub リモート / workspace 構成 / CI / cargo-ndk・xcframework のビルドパイプライン / FFI スケルトン + csbindgen / Makefile / unity-sample から `mw_init` → 無音ストリーム再生 | 4ターゲットのビルドが CI で通り、macOS Editor 上で init/shutdown が動く | なし |
| **M1. SE 再生** ★価値の核 ✅**完了** | ミキサ、ボイスプール、バス音量、ソフトクリッパ、wav ロード、即時発音、オフラインレンダリングとテスト群 | Editor と実機で SE が鳴る。**実機で Unity 実装との遅延 A/B を外部録音で計測し、目標値(§1)を満たす**。満たさない場合はここで M6 のバックエンド直叩き置換を判断 | なし(計測は外部録音方式) |
| **M2. 楽曲とクロック** ✅**完了(2026-08-25)** | Symphonia ストリーミング、リサンプル、予約再生、ポーズ/巻き戻し再開/シーク、サンプルカウンタ + タイムスタンプ相関、世代カウンタ。後半: テンプレート側 `App.Audio.Native` アダプタ実装と統合 | テンプレートのライブをネイティブ実装で完走でき、判定計測ハーネスのクロック計測(ジッタ・ドリフト)が目標値を満たす → **達成**(iPhone 14 実機でジッタ 0.402ms / 単調性違反 0 / アンダーラン 0。`docs/measurement-m1.md` §11) | **後半のみ**: テンプレート Phase 2(IF 確定 + ハーネス) |
| **M3. 実運用耐性** | ルート変化(イヤホン抜け / BT)検知と再オープン、割り込み処理、出力レイテンシ問い合わせ、アンダーラン検知・テレメトリ、iOS AVAudioSession シム(最小の Obj-C) | ルート切替・着信・バックグラウンドを跨いでもクラッシュ・無音化せず、テンプレートの自動ポーズ・オフセット切替が動く | テンプレート Phase 2(中断対応の実装) |
| **M4. 仕上げ機能** | フェード、プレビューループ、メトロノーム予約発音(キャリブレーション連携)、エディタ用の再生速度変更(リサンプル方式) | テンプレートの選曲プレビュー・キャリブレーション画面がネイティブ実装で動く | テンプレート Phase 6(キャリブレーション画面) |
| **M5. ハードニング** | 実機プロファイル(CPU / 電力)、長時間試験、UPM パッケージ仕上げ、リリース自動化、ドキュメント(統合手順・API リファレンス・設計 ADR) | ドキュメントだけ読んでテンプレート導出プロジェクトに導入できる | なし |

**M1 の A/B 計測が最重要のゲート。** ここで Unity 実装に対する優位が出なければ、
このミドルウェアの存在意義(§1)が崩れるため、先に進まず原因を潰すか計画を見直す。

## 14. リスクと対応

| リスク | 対応 |
|---|---|
| cpal では遅延目標に届かない(特に Android の performance mode / exclusive 制御) | M6 の方針どおり oboe 直叩きへ置換。Backend trait で差し替え可能にしてある |
| AAudio はルート変化でストリームが死ぬ(disconnect) | 音声スレッド外で再オープン → クロック相関を取り直す処理を M3 で必須実装。再オープン中の曲位置は内部カウンタで継続し、世代カウンタを進める |
| Bluetooth の遅延が大きく・動的 | ミドルウェアでも吸収しきれない(コーデック依存)。テンプレート側の方針(ルート別オフセット + BT 警告、テンプレート仕様「プレイヤー設定」)に従い、こちらは正確な遅延報告に徹する |
| Unity Editor のドメインリロードでネイティブ状態が残留 | init/shutdown を冪等にし、C# 側でドメインアンロード時に確実に shutdown。dylib は常駐前提で設計 |
| iOS の AVAudioSession 設定(カテゴリ・バッファ長)は Rust から直接触れない | 最小の Obj-C シム(数十行)を xcframework に同梱。M3 で実装 |
| Unity Audio 無効化で `OnAudioConfigurationChanged` が死ぬ可能性 | §6 のとおりミドルウェア側イベントに正規化して一本化。M3 で検証 |
| Symphonia の ogg シークがサンプル精度でない | シーク後にデコード読み捨てでサンプル境界へ合わせる(一般的な手法)。ゴールデンテストで精度を固定化 |
| IL2CPP / Mono 両対応の P/Invoke 差異 | コールバック不使用(M4)+ blittable 型限定でリスクの大半を回避。csbindgen は IL2CPP 実績あり |
| アダプタがテンプレート側にあることによる分裂(バインディング更新とアダプタ更新のズレ) | ABI バージョン検査(§4.8)で実行時に検出。破壊的変更はメジャーバージョン + テンプレート側アダプタの追随を同一作業で行う |
