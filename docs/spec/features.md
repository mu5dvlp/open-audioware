## 4. 機能仕様

### 4.1 バスとミキシング 【仮】

- バスは **Master / BGM / SE / Voice の固定4本**(テンプレート仕様「オーディオ抽象化」の
  `IAudioService` のバス構成に整合)。任意本数のバスツリーは作らない — 音ゲーに不要
- 各バスは音量(linear。UI 側の dB 変換はテンプレート側の責務)とフェード
  (目標値 + 時間。ブロック内はサンプル単位の線形ランプ)を持つ
- ミックスは **f32 ステレオ**で行い、モノ素材は両チャネルへ等パワー展開(M12)
- **Master にソフトクリッパを置く**(同時発音が重なった際の折り返し歪み防止)。
  通常運用でクリッパが動作しないゲインステージングを既定とし、動作した場合は
  開発ビルドでイベント(§4.6)として観測できるようにする
- 音量の即時変更・停止も内部では短いランプ(【仮】5ms)を通す(M13)

### 4.2 SE 再生 【仮】

- SE はロード時に**全デコードして PCM でメモリ常駐**(§5.2)。発音要求は次のオーディオ
  コールバックで必ず発音される(= 遅延は1バッファ + 出力レイテンシのみ)
- **ボイスプール**: 同時発音数は既定 64。枯渇時は**最も古いボイスをスティール**する
  (音ゲーの SE は短く、体感上問題になりにくい方式を既定とする)
- 同一 SE の連打(タップ SE)は重ね発音を許可する。発音制限(同一 SE の同時数上限)は
  パラメータとして持つが既定は無制限
- 音量・バス指定は発音時パラメータ。再生中ボイスの操作(停止・音量変更)は
  ボイスハンドル経由で可能とする

### 4.3 楽曲再生 【確定】

- 楽曲は**圧縮データをメモリに保持し、専用デコードスレッドでストリーミングデコード**、
  リングバッファ経由で音声スレッドに供給する(実行時のファイル IO を持ち込まない)
- 対応操作: 準備(プリロール込み)/ 予約再生 / ポーズ / **巻き戻し付き再開**
  (テンプレート仕様「中断対応」の「数秒巻き戻し + カウントダウン再開」の受け皿)/
  シーク / 停止 / ループ区間設定(選曲プレビュー用。フェードイン/アウト付き)
- **予約再生** `mw_music_play_scheduled(host_time_ns)`: 指定ホスト時刻にサンプル境界で
  発音する(`PlayScheduled` 相当)。プリロール完了前の予約はエラーではなく
  「準備完了後、可能な最速時刻」へ繰り下げてイベントで通知する 【仮】
- 準備状態(ロード中 / 準備完了 / 再生中 / ポーズ中)は状態問い合わせ API で取得する
  (コールバックはしない。M4)

### 4.4 音楽クロック 【確定】 — このミドルウェアの心臓部

`IMusicClock` の品質を Unity 実装より一段上げるための設計。

- 音声スレッドが「楽曲ボイスをこれまで何フレーム(サンプル)レンダリングしたか」を数える
- 出力デバイスのタイムスタンプ API(AAudio `getTimestamp` / CoreAudio の `AudioTimeStamp`)で
  「いま DAC から出ているのはどのサンプルか」を取得し、**曲位置 × ホスト単調時刻**の相関点を持つ
- FFI は `mw_music_get_position(out snapshot)` でスナップショット
  `{ song_frames, host_time_ns, sample_rate, is_playing, generation }` を返す。
  C# 側はこれを基準に `SongTimeAt(t) = song_frames/rate + (t - host_time_ns)` で
  任意時刻の曲時間を線形外挿する
- **generation(世代カウンタ)**: シーク・停止・再オープン(ルート変化)で不連続が起きるたびに
  インクリメントする。C# 側は世代を跨ぐ外挿・補間をしてはならない(不連続を跨いだ
  なめらか補間は判定時刻を歪めるため)。単調性の保証は同一世代内でのみ与える
- スナップショットは seqlock 相当の atomic 読み書きで、どのスレッドからも
  ロック無しで取得できるようにする
- ホスト単調時刻(`CLOCK_MONOTONIC` / `mach_absolute_time`)と Unity の
  `Time.realtimeSinceStartupAsDouble` の原点差は、C# 側が起動時に両方をサンプリングして
  確定させる(以後は定数オフセット)

### 4.5 スケジュール発音 【確定】

- `mw_se_schedule(id, bus, host_time_ns)` でサンプル精度の予約発音を行う。
  用途はメトロノームとキャリブレーション用クリック
  (テンプレート仕様「プレイヤー設定」のキャリブレーション画面の音源)
- 予約はソート済みキューで保持し、該当バッファのレンダリング時に**バッファ内オフセット
  サンプル位置**から発音する(バッファ境界への丸めはしない — 丸めるとキャリブレーションの
  計測値そのものが汚れる)

### 4.6 イベント通知 【確定】

- 種別 【仮】: `RouteChanged` / `Underrun` / `MusicEnded` / `MusicLooped` /
  `StreamError` / `ClipperEngaged`(開発ビルドのみ)
- C# 側が毎フレーム `mw_poll_events(buf, cap)` でポーリングする(M4)。
  呼び出し側が確保したバッファに blittable 構造体で書き込み、GC アロケーションゼロ
- イベントキューは固定容量(【仮】64)。溢れた場合は**古いものから破棄**し、
  破棄数をカウンタとして次のポーリングで報告する(黙って落とさない)

### 4.7 デコードとリサンプリング 【仮】

- コーデックは **wav(PCM)/ ogg vorbis**(Symphonia)。opus は必要になったら追加(MU2)
- SE はロード時に全デコード + 必要ならロード時にリサンプルして出力レート化(再生時コストゼロ)
- 楽曲はストリーミングデコードし、レート不一致はデコードスレッド上でリサンプル
  (リサンプラは **rubato** 【仮】)。音声スレッドにはリサンプル済み PCM だけが渡る
- ogg のシークはサンプル精度でないため、**シーク後にデコード読み捨てでサンプル境界へ
  合わせる**。精度はゴールデンテスト(§8)で固定化する
- 素材制作の推奨レートは 48kHz(モバイルの主流出力レート。リサンプル頻度を最小化する)

### 4.8 エラーモデルと ABI 【確定】

- 全 FFI 関数は**エラーコード(負の整数)返し**。列挙は `MwResult` として一元管理し、
  csbindgen で C# 側 enum も自動生成する
- ハンドルは不透明な整数 ID(ポインタを C# に渡さない)。二重解放・使用後解放は
  無効 ID エラーとして検出する(クラッシュさせない)
- `mw_abi_version()` で ABI バージョンを返し、C# 側が起動時に期待値と照合する。
  **ABI 互換の破壊は semver メジャーバージョンでのみ許可**
- ログ: 開発ビルドでは stderr / logcat / os_log へ出力。リリースビルドでは
  重要イベントのみ(イベントキュー経由で C# 側からも観測可能)【仮】
