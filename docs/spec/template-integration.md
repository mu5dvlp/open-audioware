## 6. テンプレートとの連携ポイント 【確定】

ミドルウェア側だけでは閉じない項目。テンプレート側に必要な受け口を明記する。

- **音源アセットの二形態**: Unity 実装は `AudioClip`、ネイティブ実装は**生バイト**
  (wav / ogg)を読む。楽曲カタログの「音源アドレス」は実装ごとに解決を変えられる必要がある。
  テンプレートのサンプル音源は生成スクリプト製(テンプレート仕様「サンプル音源」)なので、
  **生成時に AudioClip 用 wav と `.bytes` の両方を出力**すれば二重管理にならない
- **Unity Audio の無効化 【仮】**: ネイティブモードでは Project Settings の Disable Unity Audio を
  有効にし、全ての音をミドルウェアに通す(M8)。この設定切替はテンプレートのビルド設定側に持つ
- **ルート変化イベントの経路**: テンプレートは `AudioSettings.OnAudioConfigurationChanged` を
  使っている(テンプレート仕様「プレイヤー設定」)が、Unity Audio 無効時にこのイベントが
  機能するかは検証項目。機能しない場合に備え、ミドルウェアの `RouteChanged` イベントを
  `IAudioService` 側の通知に正規化して流す — **テンプレートのオフセット自動適用が
  どちらの実装でも同じ経路で動く**ようにする
- **譜面エディタは Unity 実装のままでよい 【仮】**: 制作ツールに低遅延は不要。
  波形表示も `AudioClip` ベースの既定実装をそのまま使う
- **アプリライフサイクル**: バックグラウンド移行・復帰・オーディオ割り込み(着信)は
  C# 側から `mw_music_pause` 等を明示的に呼ぶ(テンプレート仕様「中断対応」に従属し、
  ミドルウェアが勝手にポーズしない)。ただしストリーム自体の切断(AAudio の disconnect 等)は
  ミドルウェア内部で再オープンし、イベントで通知する
- **Unity Editor のドメインリロード**: init/shutdown を冪等にし、C# 側でドメインアンロード時に
  確実に shutdown する。dylib は常駐前提で設計する
